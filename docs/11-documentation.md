# 文档规范

类型：开发参考。文档必须让没有聊天记录的新开发者理解当前规则和实施边界。

## 每类事实的归属

| 文件或目录 | 维护内容 |
| --- | --- |
| README.md | 项目入口、当前进度、真实可运行命令 |
| AGENTS.md | Agent 每次任务必读的短规则，链接详细文档 |
| DESIGN.md | 产品定位、核心路径与设计不变量 |
| docs/03-architecture.md | 模块依赖、装配、生命周期、网络和持久化机制 |
| docs/04-tool-contracts.md / schemas | 工具字段语义 / 机器可读 Schema |
| docs/06-upstream-policy.md | 用户确定的搜索准入要求 |
| docs/07–11 文档 | 技术栈、编码、工程、测试、文档规范 |
| docs/12-sites-evidence-scoring.md | 站点限定、原文证据、相关性和置信等级 |
| docs/13-evidence-presentation.md | 段落证据续读、前端元数据与溯源语义 |
| docs/decisions | 决策、替代方案和取舍；不代替执行结果 |
| docs/verification | 执行环境、实际命令和结果、未验证项 |
| docs/references | 外部项目及论文的核查记录，不是运行依赖 |
| 模块 README | 模块职责、接口使用与独有约束 |

同一规则的完整表述只放在所属文档，其他位置用简短摘要和链接。不要复制整张工具字段表到 README、AGENTS 和多个模块文档。

## 写法

文档以中文为主，代码名和稳定机器字段保留英文。参考文档用于查规则，教程用于按顺序完成任务；长篇混合内容拆开。段落一句接一句说明主体、行为、条件与后果，不记录 Agent 的推理过程。

普通段落每段一个物理行，编辑器软换行；文件 UTF-8、LF、末尾恰好一个换行。列表和表格正常分行，表格只用于真正需要对比或映射的内容。相对链接引用仓库文件，不能把本机绝对路径写成运行前提。

范例注明是真实记录、构造数据还是伪代码。不可执行的片段使用 text fence 或明确说明依赖前提；声称可以执行的代码需要验证。官方页/论文标链接和核查日期，价格、版本、服务条件变更时重新核查。

## 设计与实现状态

规范可以先于代码存在，但文档开头必须说明它定义目标行为。当前可用能力与命令统一在 README；实施步骤统一在 roadmap；检查结果统一在 verification。不要在多个架构段落反复添加易过期的“已实现”标记。

schema_version、快照字段、错误语义等改变时，同步更新对应文档与示例。生成的 TypeScript 类型不手改，不从实现中复制一份未经校验的类型表到文档。

ADR 使用 [模板](decisions/template.md)，按 proposed/accepted/superseded/rejected 记录决策状态，另列 implementation 状态；不要把 accepted 当测试通过。已有 ADR 仍描述同一决策时更新它，改变决策方向时新增后继 ADR 并互相链接。

## 文档验收

检查内部文件链接、示例语法、当前命令真实性、文档间矛盾和未声明前提。让新读者回答：如何开始、用什么栈、不能接哪些上游、代码放哪、错误如何返回、什么检查算完成。无法从项目文件得到答案时补到所属文档，不依赖聊天记录解释。
