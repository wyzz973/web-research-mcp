# 看懂与调试一次搜索

本页针对初次接触检索系统的使用者。工作台从 Node 24 环境执行 `pnpm workbench`，打开命令输出地址的 `/trace`，默认是 http://127.0.0.1:18900/trace。SearXNG 仍单独通过 `pnpm searxng:start` 启动，无需 Docker。

## 第一次怎么观察

1. 打开“过程观察”，先看上方六步流程。最后“LLM 组织回答”位于外部，本服务没有执行模型推理。
2. 输入 `MCP tools structuredContent`，限定域名 `modelcontextprotocol.io`。保留“提取前 3 条原文”，点击“运行并观察”。这会真正联网。
3. 左侧出现本次运行，中间逐渐出现真正开始的步骤。总耗时不等于所有子步骤时间相加，因为父步骤包含子步骤，多个来源可以并发处理。
4. 点击中间的步骤，右侧先用中文解释它为什么存在，再展示实际输入、输出、状态和时间。计数是真实观测；缺失信息显示未知。瞬时事件标“事件”，排队真正等了多久查看“开始上游请求”的 wait_ms。
5. 用“小白逐步回看”的上一步/下一步逐项阅读。这个操作不重新联网，不会重放已经发生的 HTTP 请求。
6. 找到“决定本次使用的引擎”或引擎响应，检查实际参与、被跳过的引擎及错误；不要把本机 SearXNG 的正常 HTTP 200 等同于每个引擎都成功。
7. 展开某条来源的证据步骤，查看 DNS、robots、下载、内容检查、正文提取、快照和选段。验证失败之后没有执行的步骤不会被画成成功。
8. 取消一次调用，观察 cancelled。切换 webfetch，输入一个公开网页 URL，查看单独抓取的流程；对已有快照续读的 MCP 调用，则没有下载和解析步骤。

## 每一层负责什么

| 步骤 | 小白理解 | 实际工作 |
| --- | --- | --- |
| 参数解析 | 把订单写清楚 | 校验 query/sites/数量/排序和预算 |
| 调度/缓存 | 查能否复用，再决定什么时候出发 | 完整成功页短缓存、合并重复请求、控制启动间隔 |
| SearXNG | 搜索中转站 | 向准入匿名引擎发请求，汇总候选与失败 |
| 过滤/去重/排序 | 整理书单 | 严格域过滤、URL 去重；默认上游，BM25/MMR 可选 |
| 固定候选池 | 保存这次书单 | 分页时不换一份搜索结果 |
| 读取网页 | 打开选中的书 | 受控 HTTP、robots、跳转与大小检查 |
| 正文提取 | 找到书里的正文 | 移除网页导航噪声，生成文本/Markdown |
| 快照与证据 | 给摘录标页码 | 保存文本哈希、片段字符范围与续读位置 |
| 外部 LLM | 读材料并写回答 | 由调用方完成；本服务不宣称核验事实真假 |

## webfetch 的技术

Node.js 的 Undici 发 HTTP 请求；node:dns、ipaddr.js 等检查解析地址，并把验证过的地址固定用于连接。robots-parser 检查网站抓取规则。JSDOM 在独立 worker 中解析静态 HTML，Mozilla Readability 提取可读正文，Turndown 与 GFM 插件转换 Markdown。SQLite 保存正文快照与续读游标。

这不等于完整浏览器：不会运行页面 JavaScript，不登录网站，不自动处理验证码。当前支持 HTML/XHTML、纯文本与 Markdown；PDF、动态浏览器后备不在本版。完整原文是提取后的正文快照，不是整个网页资源包。

## 免费搜索如何更可靠

已落地：完整成功页缓存 60 秒、相同在途请求合并、最多 2 个上游并发且启动至少间隔 1 秒、现有引擎冷却/半开恢复、有效部分结果保留、所有失败不误报 empty。LLM 能用 trace_id 关联到本地观测，但正常工具响应无需包含整个 trace，避免浪费上下文。

LLM 使用建议：先用 websearch 的摘要发现候选；需要引用时再要求 evidence_mode=extract 或针对 URL 调用 webfetch；后续用游标读取已有证据，不重复抓取同一正文。结果的 relevance、ranking.score、confidence 含义不同，trace 不会把它们转换为事实正确概率。

当前明确的限制：partial 不缓存，验证码仍可能阻止全部结果；缓存/节流按进程隔离，多客户端跨进程统一配额尚未实现。没有承诺 SLA。下一步应通过此页面确认请求数量和失败分布，再考虑小而快的查询预算、显式带采集时间的部分结果缓存、统一出站调度、受控补召回与更有代表性的评估。

## 记录与隐私

普通 MCP 默认仅元数据，observability.capture_content=true 才存有界查询/正文预览；观察页由明确勾选项按请求开启。取消勾选后仍保存步骤/耗时/计数。会话令牌、Cookie、口令、游标等不进入记录，URL 查询部分始终去掉。因脱敏/预算缺失的内容不从其他数据猜回。

trace 数据在配置 storage.directory 的 traces.sqlite，最多最近 100 次/24 小时，不进入 Git；正文快照仍在 snapshots.sqlite。多进程使用同一 data 目录时，工作台能看到它们写入的 trace；使用不同 WEB_RESEARCH_DATA_DIR 时相互隔离。重启保留已完成记录，但未开启观测时的旧调用不能补录。

GET /api/traces 返回有界摘要；GET /api/traces/:id 返回详细步骤，均要求本机会话校验。采集存储故障不改变搜索结果，/api/status 的 tracing 会显示 storage_unavailable。完整决策与边界见 [ADR 0008](decisions/0008-local-observability.md)。
