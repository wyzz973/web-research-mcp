# 架构与路线

状态：设计草案，尚未实现。这一页说明 [web_search](web-search.md) 和 [web_fetch](web-fetch.md) 背后的系统。工具本身的设计是重点，这里只写到足以支撑它们的程度。

## 1. 目标与边界

**要做到**

- 给任何 agent harness 用：MCP（stdio 和 HTTP）、CLI、库，三种形态共用一份契约。
- 多来源：付费 API、厂商匿名免 Key 档、官方免 Key API、网页抓取、用户自建端点，统一成适配器。任何一个来源消失，系统降级而不是不可用。
- 高可用和并发：按额度和健康状态路由；多个 agent 进程并发时共享额度、缓存和熔断状态。
- 成本可控：少调用、调便宜的、少占 token。
- 一条命令装好：Windows、macOS、Linux，不需要 Python、Docker、原生编译。

**不做**

- 不自建全网索引；不在内部调用大模型；不做浏览器操作型 agent。
- 不绕过验证码、付费墙、登录；不轮换身份规避限流；不接入国内搜索引擎。
- 首版不做多租户托管服务。

## 2. 分层

```
 MCP stdio | MCP HTTP | CLI | 库            薄壳：校验参数、呈现输出、退出码
--------------------------------------------
 核心：规划 -> 选来源 -> 执行 -> 归一与融合 -> 打包
--------------------------------------------
 阅读器：抓取 -> 提取 -> 分段 -> 快照 -> 目录 / 查找 / 挑段落
--------------------------------------------
 状态（单个 SQLite 文件）：查询缓存、快照与本地语料、额度账本、令牌桶与熔断、执行轨迹、录制带
--------------------------------------------
 来源适配器：付费 API | 匿名免 Key 档 | 官方免 Key API | 网页抓取 | 自建端点
```

依赖只能向下。适配器之间互不依赖。核心不引用任何 MCP 或 CLI 的代码。

## 3. 来源适配器

```ts
interface SourceAdapter {
  id: string
  capabilities: {
    nativeSiteFilter: number // 一次调用最多带多少域名，0 表示不支持
    multiQuery: number // 一次调用最多带多少查询
    maxResults: number // 含在单价里的最大条数
    returnsExcerpts: boolean
    recency: boolean
  }
  cost: { unitUsd: number; freeQuota?: { amount: number; period: 'day' | 'month' | 'once' } }
  storagePolicy: 'persist' | 'short_ttl' | 'transient' // 按该厂商的条款
  search(request: SourceRequest, context: CallContext): Promise<SourceResult> // 失败抛带类型的错误
}
```

| 层 | 来源 | 说明 |
| --- | --- | --- |
| 1 付费，用户自带 Key | 首批 Parallel、Exa、Tavily；第二批 Brave、Serper、Perplexity Search | Key 只从环境变量读取，沿用各家惯用的变量名 |
| 2 匿名免 Key 档 | 首批 Exa、Parallel、Tavily；第二批 You.com、Firecrawl | 与付费档是同一个适配器：有 Key 走付费，没有走匿名 |
| 3 官方免 Key API | Wikipedia、MDN、StackExchange、GitHub、HN、npm、crates.io、arXiv、OpenAlex | 由 `sites` 和标识符直达触发 |
| 4 网页抓取 | Bing、DuckDuckGo | 只做兜底。实测在代理出口 IP 下经常被拦或返回跑题结果 |
| 5 自建端点 | SearXNG 等 | 可选 |

## 4. 选来源

1. 过滤：健康、有额度、能力满足（例如需要原生域名过滤）。
2. 排序：配置了 Key 的来源优先，其次是匿名档；同一级里当天用得最少的先用。匿名档是厂商补贴的共享资源，最脆弱，所以放在后面；带 Key 的花费由每日预算封顶，预算用完后只用免费来源。配额用尽（例如 Tavily 返回 432）的来源直接排除到本地次日零点，不再反复试探。
3. 按 `depth` 取来源：`fast` 取 1 个；`standard` 取 1 个，结果不可靠时再补 1 个并融合；`deep` 最多 3 个并行融合，受预算上限约束。同一优先级内按当天用得最少的先用。匿名来源每天有自我限额，失败只冷却、不重试。
4. 执行：选中的来源并行发出；相同查询的并发请求合并；每个来源有软超时，超时后不等它，晚到的结果进入候选池；失败按类型进入冷却（被拦 300 秒起，其他 30 秒起，指数增长）。
5. **跨进程协调放在 SQLite 里**：冷却状态和额度账本都写进同一个数据库，用短事务更新；命令行每次都是新进程，如果冷却只在内存里，每次运行都会重新去敲已经被封的来源。多个 agent 进程因此天然共享额度，默认不需要常驻服务。常驻的 HTTP 服务是后期的可选形态。

## 5. 缓存与本地语料

| 层 | 内容 | 有效期 |
| --- | --- | --- |
| L0 | 合并同时进行的相同请求 | 请求期间 |
| L1 | 按规范化查询缓存候选池 | 时效类 15 分钟到 6 小时；普通 1–3 天；限定文档站 7 天；零结果 1 小时；错误不缓存 |
| L2 | 相近查询复用：内容词高度重合，且数字、版本号、引号短语完全一致 | 同 L1，输出里标明是相近命中 |
| L3 | 本地语料：我们自己抓取的页面段落进 FTS5，中文用 trigram 分词 | 30 天，按容量淘汰，用条件请求验证是否过时 |

厂商返回的搜索结果按各家条款处理：Brave 明文禁止持久缓存，只做进程内的短期复用；其余默认只缓存 24 小时。长期保存的只有我们自己从原站抓取的内容，它不受搜索厂商条款约束。

## 6. 成本

- 账本记录每个来源的请求数和估算花费；厂商回显实际花费时用实际值。单价表随包发布并标注日期，用户可以覆盖。
- 三道上限：每次调用的 `max_tokens`；每个进程的搜索次数和花费；每日和每月的美元上限。到上限后降级到免费层，并在输出里说明。
- 省钱的结构性手段：`sites` 合并成一次调用；付费来源默认不翻页；不买厂商的正文，自己抓取；支持一次多查询的来源合并调用；缓存。

## 7. 安全

见 [web_fetch 设计](web-fetch.md) 第 11 节和 [共同约定](conventions.md) 第 8 节。另外：MCP 的 HTTP 形态只绑定回环地址，校验 `Origin`，要求令牌；凭据不写入日志、轨迹和录制带。

## 8. 可观测与回放

每次调用写一条执行轨迹：步骤、耗时、来源状态、缓存、花费，默认不含查询和正文。`--record` 把上游响应和抓取内容写进录制带，`--replay` 完全离线、确定性地重放。回放是给 harness 开发者和 CI 用的：agent 的测试可以不联网。

## 9. 技术栈与分发

- TypeScript（strict、ESM），Node 22 及以上。harness 生态以 npm 和 `npx` 为主，旧模块可以直接移植。
- 已实测 Node 22、24、25 内置的 `node:sqlite` 自带 FTS5、trigram 分词和 WAL，因此不再有任何原生依赖。
- 依赖从严：MCP 官方 SDK、Readability、一个 DOM 实现、Turndown、undici、公共后缀数据、Ajv。TLS 指纹档（`impit`）和浏览器档（`playwright-core` 驱动本机已装的 Chrome 或 Edge）是可选依赖，用到才加载。
- MCP 同时应答新旧两代协议：2026-07-28 的无状态版和之前的握手版。
- 分发：npm 包加固定版本的 `npx`；MCP Registry；各 harness 的薄包装；一份 `SKILL.md` 同时教 MCP 和 CLI 两条路。
