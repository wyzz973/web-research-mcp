# ADR 0007：引擎诊断、排序实验与本地验收工作台

状态：接受。日期：2026-09-10。

## 背景与决定

原生 SearXNG 已可运行，但免费上游仍会封锁或暂停。需要明确观察到的失败、冻结候选评估排序，并让使用者在浏览器中检查原文证据。

Provider 增加进程内逐引擎诊断与有界冷却。只根据经过校验的 `unresponsive_engines` 与结果引擎观察更新状态；端点连通故障不归因于具体引擎。SearXNG 的 suspended 标记没有剩余时长，本地退避不冒充上游恢复时间，不清空上游暂停缓存。恢复由下一次调用在冷却后触发单请求探测，无后台搜索。

`websearch.ranking_mode` 和部署 `ranking.mode` 支持 upstream、bm25、bm25_mmr；默认 upstream。实验排序基于去重并限定域后的标题/摘要候选池，在冻结和分页之前执行，补抓的是排序后的当前页。最多 200 候选，算法的输入文本、参数、版本和稳定平分规则有界。`rank` 是最终顺序；实验结果的 `ranking` 另行保留原名次、原始排序分数和候选池大小。原有 relevance、confidence 保持独立。已有检索游标因 fingerprint 增加排序设置可能不匹配；重新搜索即可，正文快照格式不变。

RRF 只能消费真实独立排名列表。本版 SearXNG 聚合结果没有逐引擎完整独立名次，不能从 engines 标签伪造列表。向量和模型精排不自动启用。

评估查询集、冻结候选、标注和报告分开保存。人工、Agent 与构造 fixture 标签必须明确区分。空池、失败、未标注不记为通过；比较使用同一候选池，所有改善只针对实际评估范围成立。

新增 `src/workbench` 作为本地 HTTP 展示适配器，只监听 127.0.0.1，不作为远程 MCP transport。使用现有工具编排、Schema、SnapshotStore 和抓取策略。`src/tools/runtime.ts` 负责 stdio 与工作台共享的应用装配。HTTP 适配器拥有连接、同源校验、请求大小与并发限制、浏览器断开取消；应用生命周期在请求结束后关闭 Provider、loader 和 store。

## 浏览器边界

页面启动时注入一次随机会话 token，API 要求同源自定义请求头；验证 Host/Origin，避免其他站点或 DNS 重绑定调用本地工具。token 不写 URL、不记录日志。静态资源使用固定路由白名单。网页内容作为文本展示，不运行抓取到的 HTML/Markdown。CSP 限制脚本、连接和嵌入；站点图片仍为第三方元数据，不以图片加载成功证明来源权威或事实真实性。

该工作台无远程监听、用户账户、多租户或端点重配置接口。扩展为公网服务需要独立设计。

## 验证

Provider 冷却/恢复、部分失败、取消；同一候选池排序与分页、模式不匹配；评估指标的独立已知样例；真实 HTTP 会话保护、并发限制、断开取消与 SSRF；浏览器搜索、证据、续读、移动布局与错误展示。执行结果以本次验证记录为准。
