# ADR 0004：0.1.0 运行实现与验证边界

Status: accepted

Implementation: implemented

日期：2026-09-08。

## 问题

文件设计需要落实为可发布的真实 stdio 服务，同时避免独立模块各自定义来源身份、生命周期和验证成功条件。

## 决策

采用固定版本 SDK 2 和 fromJsonSchema 接入作者 JSON Schema，Ajv2020 执行校验；类型生成器将带兄弟约束的 $ref 转换为等价 allOf 后生成，防止遗漏 relevance 字段。源码 strict 检查保持开启，skipLibCheck 只跳过第三方声明实现检查；自己的源码和生成 wire 类型均受类型检查。

公开网页使用 fetch/network 的 DNS 固定连接与公网策略；操作员配置的 SearXNG 端点使用独立、受限且禁跳转的 Node HTTP 请求，作为模块边界中的明确例外。SearXNG 请求只传 engines，不传 categories；实际镜像会将二者引擎集合合并，导致超出指定白名单。

SQLite 直接在本版本实现，使用 records 表与 PRAGMA user_version=1 保存不可变快照、候选池、页面响应和游标；不并行建设第二套内存生产存储。数据容量以保守 WAL 预留限制主库页面数，仍无空间则回滚并报错，保留有效记录。

来源、快照和游标使用内部品牌类型与统一工厂；wire 保持原字符串格式。相同 search cursor 并发共享页面构建，取消首调用不能取消其他仍活跃调用。取消路径等待所有已启动证据任务清理结束，超时且已有候选保留 partial。

正文解析使用独立 worker，并分别约束网络并发、解析并发、内存与时限。纯 CSS 解析噪声不写日志；非 CSS 诊断保留或失败。运行 state/实例 secret 不纳入 Git。

## 考虑的替代方案

**M1 先内存、M2 再持久化。** 本次用户要求完整可验收功能，直接完成 SQLite 与重启测试，减少两套存储的切换成本。

**允许搜索结果来自实例其他默认引擎。** 实测确实会发生，但放宽验证会破坏显式准入；修正 SearXNG 请求参数，保持严格返回白名单。

**让相同 cursor 的所有调用共享首调用取消信号。** 会错误取消未取消的调用者；仅共享一次已清理完毕的结果，未取消者必要时重新构建该页。

**仅验证源码或依赖软链接目录。** 无法证明实际 tarball 含全部运行资源；采用干净目录安装真实压缩包并调用 MCP 入口和解析 worker。

## 后果与验证

本版本限定 Node 24，固定镜像及匿名引擎清单。公开仓库通过离线 CI，真实上游单独记录；网络封锁不靠 Key 或付费代理绕过。测试结果见 [实施验收](../verification/2026-09-08-implementation.md)。向量/神经排序、动态浏览器、PDF、多租户 HTTP 服务仍为后续独立功能。
