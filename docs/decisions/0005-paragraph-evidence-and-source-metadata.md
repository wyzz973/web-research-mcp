# ADR 0005：完整段落证据和可溯源展示字段

Status: accepted

Implementation: implemented

日期：2026-09-09。

## 问题

现场测试发现短句证据偏向通用介绍，并在软换行处出现不完整句子；前端也缺少站名、图标和可展示的来源元数据。用户确认增加证据量和这些字段。

## 决策

段落级选段默认每结果 3 段、每段 1600、合计 4000 字符，使用稀有/未覆盖查询词优先但保持原文和既有 relevance 定义。固定候选计划独立保存，webfetch 的 opaque cursor 可打开 evidence 视图；snapshot_cursor 保留连续完整文档视图。

从原 HTML 声明获取来源展示元数据，在 Readability 修改 DOM 前读取。favicon 候选、网页声明和资源可用性分开标记，不下载图标，不引入 Key、图标服务或模型依赖。

公共契约升级为 0.3-draft，包版本 0.2.0；source-metadata 是单独的作者 Schema，生成命令同步内联定义和 wire 类型。快照新增可选 metadata、SQLite records 增加 evidence kind，SQL 结构不变，旧文档仍可读取。搜索池升级为版本 2，旧池明确不兼容。

## 考虑的替代方案

**仅把字符上限调大。** 不能修复通用介绍优先和软换行截句；必须调整候选构造与选择。

**每条强行返回固定字数。** 会引入无关内容；较短但充分的证据仍可少返回。

**让更多证据游标重新搜索/抓取。** 会改变原文与评分，失去复核基础；计划绑定已有不可变快照。

**使用第三方 favicon 聚合接口。** 增加对外依赖及浏览隐私暴露；直接返回可追溯声明和明确的约定地址。

**把 og:image 作为网站 logo。** 页面封面不等于站点身份，分别输出 image_url 与 logo_url。

## 后果与验证

首次证据响应更长，但受每段、每结果、候选数及部署上限约束。普通查询不额外抓所有站点。验证覆盖跨段/Unicode 原文、完整句、预算和分隔符、重启与过期、元数据声明/危险 URL、实际来源归属，以及真实 MCP 往返。
